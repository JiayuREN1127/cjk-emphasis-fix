# 中文标点旁的强调：实时预览与源码改写

`请看**示意图。**然后翻页` 中，闭合的 `**` 前是句号，后面紧接汉字。按 [CommonMark 的强调规则](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis)，这里的 `**` 不满足闭合条件。上游 `0.3.6` 的插件已经能在实时预览中补上这段加粗。下面对照的是另一层问题：一句话里还有代码、公式或链接时，哪些星号仍属于正文？

## 实时预览：该补的加粗和不该补的加粗

在 Obsidian 的实时预览中启用插件，把下面四行复制到空白笔记，再将光标移到其他行。以下对照记录的是上游 `326e197` 与本次修改的扫描结果；右栏说明在编辑器中应检查什么，不代表已在特定主题下实测。

```markdown
请看**示意图。**然后翻页
请将**菜单里的 `保存` 按钮。**设为默认
正文 $**预算。**暂定$ 到此
参见[[清单|**样品。**待核]]即可
```

| 场景 | `0.3.6` 扫描结果 | 修改后的扫描结果与预览检查点 |
| --- | --- | --- |
| 普通正文（对照） | 找到一段加粗 | 仍只找到「示意图。」；后面的「然后翻页」不应加粗。 |
| 加粗里嵌有行内代码 | 没找到加粗 | 找到横跨 `保存` 的一整段加粗；反引号内仍是代码，「设为默认」不属于加粗。 |
| 单美元符号包住的公式 | 在公式内找到一段加粗 | 不再命中；公式如何显示由数学渲染器决定。 |
| 双链的显示文字中含星号 | 在双链内找到一段加粗 | 不再命中；插件不应给链接显示文字额外添加加粗。 |

旧扫描器先从行里剔除代码区间，再分别扫描剩余片段。因此第二行的一对 `**` 被切到两个片段里，无法配对。相反，旧扫描器只识别双美元符号公式，也没有把双链排除在外，于是后两行里本不属于正文的星号又被配成了对。

修改后的预览扫描器区分两件事：代码里的标记不能拿来给正文配对，但代码两侧的正文标记仍可以互相配对。它也区分代码、公式和双链各自占用的范围。遇到跨行代码时，它先在整篇笔记中定位代码，再扫描同一行剩下的正文，而不是跳过整行。若编辑器把强调样式延伸到了闭合标记之外，插件只在多出的正文范围恢复普通样式，避开代码、公式和链接等受保护的范围。

## 手动改写：什么情况下会动笔记

实时预览只改显示。会移动标点的是单独的「修复当前笔记」命令，本次修改后默认不可用。要验证改写行为，请用临时笔记，先在设置中开启实验性源码改写，再手动运行命令。

1. 笔记里只放第一行 `请看**示意图。**然后翻页`。两个版本都给出一处改写：`请看**示意图**。然后翻页`。这不是新增功能。
2. 撤销改写，在下一行加入 `资料见[目录](index.md)`，再运行命令。旧版仍会改第一行；新版整篇不改，包括看似安全的第一行。这项限制只影响改写，不会关闭实时预览。

这是一条保守的整篇检查，不是只跳过链接所在行。只要出现方括号、反引号或 `<`、`!`、`$`、`|`、`%`、`&` 中的任一字符，命令就不提出改写。因此普通句子里即使只有一个半角感叹号，也可能让整篇笔记保持原样。

上述四行预览输入和两种笔记内容分别通过两个版本的扫描器对照。仓库的 `npm test` 另有跨行代码、转义标记、文首元数据及强调样式超出边界的回归用例，见[扫描器测试](../tests/scanner.test.mjs)。测试不启动 Obsidian，不能代替对主题样式和光标交互的检查。
